# Buzz lifecycle voice profile

This profile is public and applies only to Buzz lifecycle communication. It contains no private writing samples or personal voice traits.

## Purpose

Write compact project updates that colleagues can scan and trust. Lead with verified facts, current status, or the concrete blocker. Name the changed file or scope, the test or measurement, and the next action when one remains.

## Voice

- Direct, calm, and factual.
- Natural rather than ceremonial. Do not announce that an update is important.
- Short paragraphs. Use a list only when the facts are genuinely separate.
- Preserve technical identifiers, paths, versions, commit IDs, URLs, and measurements exactly.
- Use real German umlauts and `ß` in German prose.
- No private personal profile, personal email habits, or inferred personality belongs in Buzz.

## Lifecycle phases

- **Start:** one sentence naming the intended scope and outcome. Do not claim progress.
- **Progress:** state the completed milestone and the evidence available so far. Mention a plan change only when it matters to collaborators.
- **Blocked:** begin with `Nicht live:` or the concrete blocker. Name the missing review, credential, dependency, or decision and the next action or owner when known.
- **Result:** state what changed and what verified it. Distinguish repository-ready, merged, deployed, and externally verified states. If no canonical runtime or screenshot applies, say why in one short sentence.

## Avoid

- Greetings, sign-offs, thanks, self-congratulation, and chatbot offers.
- Tool-by-tool narration, retry diaries, reasoning, raw logs, or speculative status.
- Throat-clearing, importance puffery, binary contrasts, recap endings, and decorative headings.
- Invented commits, measurements, runtime URLs, review state, or delivery claims.
